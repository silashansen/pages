Hvad er Kiro & Agentisk AI?

Kiro kort fortalt

Kiro er et agentisk AI IDE fra AWS, bygget på Code OSS (VS Code-fundament). Det er ikke bare auto-complete — det er en AI-agent der kan planlægge, analysere, skrive kode, køre tests og dokumentere.

Kiro bruger Claude Opus 4.6 (Anthropic) som vores primære model.

Kiro er cloud-agnostisk — det virker med enhver tech-stack og enhver cloud-provider.

Det store skifte

🔇 ChatGPT-æraen (2022–2024)

AI som samtalepartner. Du stillede spørgsmål, fik tekst tilbage, og copy-pastede selv. Du var mellemmanden.

"Kan du skrive en funktion der…" → kopier → indsæt → ret fejl manuelt → spørg igen

⚡

🔊 Agentisk AI (2025→)

AI som autonom aktør. Den læser din kode, skriver filer, kører kommandoer, opdager fejl og retter dem — selv.

"Tilføj validering på dette endpoint" → Kiro analyserer → implementerer → tester → done.

Paradigmeskiftet: AI gik fra at snakke om kode til at skrive og køre kode. Det er forskellen mellem en rådgiver og en medarbejder.

Hvilke opgaver er egnede til Kiro?

Tænk på det som en junior-senior skala: hvornår er AI en god co-pilot?

✅

Gode kandidater

  • Boilerplate-kode og CRUD-operationer
  • Enhedstests og integrationstests
  • Dokumentation og README-filer
  • Refaktorering af legacy-kode
  • Fejlsøgning med log-analyse
  • Migration af konfigurationer (fx IaC)
  • API-integration og client-generering
  • Database-skemaændringer og migrationer
  • Kode-reviews og kvalitetstjek
⚠️

Kræver ekstra opmærksomhed

  • Sikkerhedskritisk logik (autentificering, kryptering)
  • Kompleks forretningslogik med skjulte regler
  • Performance-kritisk kode (timing, concurrency)
  • Arkitektur-beslutninger i store systemer
  • Kode der interagerer med ukendte legacy-API'er
Tommelfingerregel: Jo mere kontekst Kiro har, jo bedre resultat. Legacy-kode kræver god spec og klare instrukser.

IDE vs. CLI

Kiro tilbyder to måder at arbejde — vælg den der passer til opgaven.

🖥️ Kiro IDE

  • Visuel editor (VS Code-baseret)
  • Spec-drevet workflow med UI
  • Agent Hooks (automatiserede triggers)
  • Kiro Powers (plugins on-demand)
  • Multimodal input (billeder, diagrammer)
  • Supervised + Autopilot modes

Bedst til: Feature-udvikling, spec-arbejde, visuelt review af ændringer, komplekse projekter.

⌨️ Kiro CLI

  • Terminal-baseret, interaktiv loop
  • Fungerer over SSH
  • Hurtig fejlsøgning og bug-fixing
  • Workflow-automatisering
  • Pipeline-integration
  • God til remote-servere

Bedst til: Hurtige opgaver, server-debugging, CI/CD-integration, automatisering i scripts.

det ændrede alt

Styrelsen for Fødevarer, Landbrug og Fiskeri

Tool Use

Før og efter tools

🔇 Uden tools (ChatGPT-æraen)

AI'en kunne kun producere tekst. Den kunne foreslå kode, men den kunne ikke:

  • Læse filer i dit projekt
  • Skrive eller redigere filer
  • Køre kommandoer i terminalen
  • Kalde API'er eller databaser
  • Verificere om koden virker

Du var copy-paste-mellemmand.

🔊 Med tools (den agentiske æra)

AI'en kan nu handle. Den har adgang til værktøjer:

  • File Read/Write — læs og skriv filer
  • Terminal/Bash — kør kommandoer
  • Web Search — slå ting op
  • MCP Servers — integrer med eksterne systemer
  • Kiro Powers — on-demand ekspertise

AI'en planlægger → handler → inspicerer → retter.

Context Window

AI'ens "arbejdshukommelse" — og den vigtigste begrænsning at forstå.

Styrelsen for Fødevarer, Landbrug og Fiskeri

Context Window

Hvad er det egentlig?

Tænk på context window som AI'ens skrivebord. Alt den skal vide om for at hjælpe dig — skal ligge på skrivebordet på samme tid.

Sådan er et typisk context window fordelt:

System
Kode & filer
Samtale
Output
Instrukser & tools Din kodebase-kontekst Chat-historik AI-svar

📏 Typiske størrelser

Claude Sonnet 4: ~200K tokens ≈ ca. 150.000 ord ≈ ca. 500 sider tekst. Det lyder af meget — men tool-definitioner, spec-filer og kode fylder hurtigt.

💡 Praktiske konsekvenser

Lange samtaler → AI'en "glemmer" starten. Mange åbne filer → mindre plads til resonering. Kiro håndterer dette via smart kontekst-styring og specs.

Context Window

Den bedste analogi

Forestil dig en utroligt kompetent konsulent der sidder ved dit skrivebord.

Hun kan løse enhver opgave — men hun har ingen langtidshukommelse. Hver morgen starter hun forfra.

Alt hun ved om projektet, skal du lægge foran hende hver gang. Specs, kode, noter, krav — alt.

Jo bedre du forbereder det der ligger på skrivebordet, jo bedre arbejde leverer hun.

🎯 Derfor er specs vigtige

Kiros spec-drevne tilgang løser netop dette: specs er en kompakt repræsentation af alt det vigtige — krav, design, plan — som altid er tilgængelig i context window.

Uden specs? Så skal agenten selv udlede al kontekst fra koden. Det bruger tokens og giver dårligere resultater.

🧹 Gem pointer — start frisk

Når du når frem til vigtige beslutninger eller arkitektur-valg: skriv dem ned i et dokument (fx en markdown-fil i projektet).

Start derefter en ny, tom kontekst og referer til dokumentet. Så slipper du for al den støj fra blindgyder og forsøg der ikke ledte nogen steder.

Ren kontekst = bedre resultater.

Sikkerhed & Guardrails

Kontrol, datahåndtering og compliance — det vi skal have styr på.

Styrelsen for Fødevarer, Landbrug og Fiskeri

Sikkerhed

Datahåndtering og kontrol

🔒

Data-beskyttelse

  • Via IAM Identity Center: ingen data bruges til modeltræning
  • Kiro kører lokalt — din kode forbliver på din maskine
  • Kun prompts og kontekst sendes til AI-modellen
🛡️

Operationelle guardrails

  • Supervised Mode: gennemgå hver ændring før den gemmes
  • Autopilot Mode: definer "Trusted Commands" — alt andet kræver godkendelse
⚠️ Vigtigt for vores team: Vi arbejder med myndighedssystemer. Vær altid bevidst om hvad der sendes som kontekst — undgå persondata, nøgler og credentials i prompts.

Sikkerhed

Best practices for vores team

1️⃣

Brug Supervised Mode

Altid for sikkerhedskritisk kode. Gennemgå ændringer inden de gemmes.

2️⃣

Undgå hemmeligheder

Aldrig paste credentials, tokens, persondata eller API-nøgler i chat. Brug env-variabler.

3️⃣

Review altid output

AI-genereret kode er et forslag. Samme review-standard som for menneskeskrevet kode.

4️⃣

Spec-first tilgang

Definer krav og regler i specs. Det giver AI'en klare rammer og mindsker hallucination.
